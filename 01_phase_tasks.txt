DAFTAR TUGAS PER FASE: COSMIC JOURNEY
Saya akan menulis "Kerjakan FASE N". Kerjakan hanya fase itu, sesuai Master Context.

=====================================================================
FASE 0: Fondasi navigasi dan state
=====================================================================
Siapkan rangka saja. Belum ada section baru yang lengkap.
1. Tambah 2 section id baru ke alur: 'wishing' dan 'gallery', setelah 'ending'. Buat file placeholder minimal (Wishing.jsx, Gallery.jsx + CSS module) berisi judul saja, lazy-loaded di App.jsx.
2. Angkat state pengunjung ke App (atau context kecil): { name, constellationPoints, finalMessage, coords, wishSubmitted, mySubmission }. Ending mengisi state ini saat reveal; section lain bisa membacanya. Tanpa localStorage.
3. Ending: tombol X/close pada pesan konstelasi TIDAK lagi memicu HomeWarp. Sebagai gantinya pesan tertutup dan muncul tombol "Next: Make a Wish ✦" yang menuju 'wishing' (pakai transisi fade yang sudah ada). Esc di pesan menutup pesan saja. HomeWarp tetap bisa dipanggil nanti dari Secret Ending (siapkan prop/callback onReturnHome).
4. Update NavDots (jadi 6 titik), ProgressBar, dan musik per section (useAudio: tentukan mood untuk 'wishing' dan 'gallery', boleh memakai ulang track yang ada).
5. Pastikan perpindahan Ending > Wishing > Gallery dan NavDots tidak merusak alur lama.
Keluaran: file berubah/baru lengkap + ringkasan + checklist tes manual singkat.

=====================================================================
FASE 1: Wishing Star (mekanik bintang jatuh)
=====================================================================
Bangun section Wishing Star lengkap (tanpa form; saat bintang terang tertangkap, panggil callback onCaught yang untuk sementara menampilkan alert/placeholder).
- Latar langit malam konsisten dengan StarField. Judul kecil + petunjuk "Find the brightest falling star" yang memudar setelah beberapa detik.
- Spawner 5 sampai 10 bintang jatuh acak (jumlah acak tiap sesi), muncul bergantian dengan jeda acak, lintasan diagonal bervariasi, ekor gradasi. Tepat satu "bintang terang": lebih besar, ekor lebih panjang, halo berdenyut, tetapi tidak terlalu mencolok sampai terasa mudah.
- Implementasi ringan (Canvas 2D atau DOM+CSS animation, pilih yang paling hemat untuk HP). Kendali loop lewat ref/rAF.
- Hitbox sentuh minimal 48px. Kecepatan jatuh cukup pelan untuk mobile.
- Tap bintang biasa: memudar halus + riak kecil + sfx lembut, tanpa penalti. Bintang terang yang lolos layar muncul lagi di giliran berikutnya. Setelah sekitar 20 detik tanpa tangkapan, glow bintang terang naik sebagai petunjuk.
- Tap bintang terang: bintang berhenti, membesar jadi ledakan cahaya, sfx chime/reveal, lalu panggil onCaught().
- Link kecil "Skip to gallery" selalu terlihat (posisi aman di mobile, tidak tertutup apa pun), menuju 'gallery' dengan flag skipped=true.
- Hormati prefers-reduced-motion (kurangi jumlah/kecepatan, hilangkan shake).
- Bersihkan semua timer/raf saat unmount.
Keluaran: Wishing.jsx, Wishing.module.css, dan file lain yang berubah, kode lengkap.

=====================================================================
FASE 2: Form permintaan
=====================================================================
Bangun modal form yang muncul setelah bintang terang tertangkap. Data masih dummy (belum ada backend).
Spesifikasi sesuai "Keputusan Desain": nama opsional + toggle Stay anonymous (callsign otomatis, mis. "Astronaut-7F2", dibuat sekali per sesi), chip kategori, textarea maks 280 karakter + counter, rating bintang 1 sampai 5 interaktif (touch-friendly, bisa dengan keyboard), checkbox persetujuan tampil publik, opsi "Send privately to the developer".
- Teks pemberitahuan jelas di atas form: pesan akan dipajang di Gallery Astronauts, jangan isi info pribadi.
- Validasi: rating wajib, pesan wajib (min 5 karakter), persetujuan wajib kecuali mode private. Pesan error ramah dan inline.
- Field honeypot tersembunyi (disiapkan untuk fase backend).
- Layout mobile: modal scrollable di dalam dirinya sendiri, keyboard virtual tidak menutup tombol submit, tombol close jelas, Esc menutup di desktop.
- Submit memanggil fungsi layanan terpisah submitWish(payload) di src/services/wishes.js yang sekarang mengembalikan Promise dummy (delay kecil) dan menyimpan ke state App sebagai mySubmission. Pisahkan layer ini agar backend nanti tinggal mengganti isi file tersebut.
- Setelah sukses: animasi bintang permintaan naik, lalu lanjut ke Secret Ending (fase berikutnya; untuk sekarang panggil onSubmitted()).
Keluaran: komponen form, CSS, wishes.js, dan perubahan di Wishing.jsx/App.jsx, kode lengkap.

=====================================================================
FASE 3: Secret Ending
=====================================================================
Bangun Secret Ending yang muncul setelah submit sukses (hanya jalur ini yang membukanya; skip ke gallery tidak).
- Layar sinematik: bintang permintaan user menjadi bagian langit, lalu teks terima kasih bertahap (fade berurutan, cukup lama untuk dibaca): terima kasih telah meluangkan waktu menembus angkasa bersama website ini; sebut nama/callsign user.
- Tiga tombol: "Stay with my constellation" (tampilkan kembali pesan konstelasi + konstelasi dari state App, tanpa mengulang form; dari sana ada jalan kembali ke pilihan), "View the Gallery" (ke 'gallery'), "Return home" (HomeWarp yang sudah ada, memakai nama + konstelasi dari state App, lalu kembali ke Intro).
- Pastikan HomeWarp tetap berfungsi seperti sekarang (timeline, roket 2D, konstelasi nama).
- Mobile: tombol vertikal, jarak aman, tidak tertutup popup.
- Reduced motion didukung.
Keluaran: kode lengkap file berubah/baru + ringkasan.

=====================================================================
FASE 4: Gallery (data dummy)
=====================================================================
Bangun Gallery Astronauts memakai data dummy (sekitar 30 entri realistis yang bervariasi: panjang pesan, kategori, rating, anonim/bernama) di src/data/dummyWishes.js. Data diambil lewat src/services/wishes.js > getWishes({sort, category, cursor, limit}) yang sekarang membaca dummy; kontrak fungsinya harus sama dengan yang nanti dipakai backend.
- Header: judul, rata-rata rating + jumlah astronot ("4.7 ★ from 32 astronauts").
- Kontrol: sort (Newest / Highest rated), filter kategori (chip), semua touch-friendly dan tidak memakan banyak tinggi layar di HP.
- Kartu bergaya ID astronot: ikon helm, nama/callsign, rating bintang, pesan, waktu relatif, badge kategori. Teks dirender sebagai teks biasa (tanpa dangerouslySetInnerHTML).
- "Load more" per 12 kartu. State loading (skeleton), empty state, dan error state yang ramah.
- Kartu mySubmission di-highlight "Your wish" dan muncul di paling atas.
- Section ini boleh di-scroll di dalam dirinya sendiri (ingat: wrapper tinggi 100dvh); pastikan NavDots, music player, dan tombol kembali tidak menutupi konten di mobile.
- Tombol keluar: "Back to the stars" dan (jika user datang dari Secret Ending) "Return home".
- Latar: langit dengan bintang kecil bersinar; opsional bintang-bintang kecil berdenyut mewakili tiap komentar, tetapi tidak boleh mengganggu keterbacaan.
Keluaran: kode lengkap file berubah/baru.

=====================================================================
FASE 5: Poles dan QA (tanpa fitur baru)
=====================================================================
Audit berbasis snapshot. Untuk setiap temuan tulis: file, bagian kode, masalah, perbaikan. Beri kode lengkap hanya untuk file yang diperbaiki. Hal yang hanya bisa dicek di perangkat nyata (address bar HP, keyboard virtual) masukkan ke daftar "Tes manual", jangan diklaim sudah beres.
Periksa dan perbaiki:
1. Alur lengkap: Ending > X > Next > Wishing > tangkap > form > secret ending > tiap tombolnya; juga Wishing > Skip > Gallery.
2. Mobile (lebar 360 sampai 430px, address bar browser HP naik-turun): tidak ada elemen terdorong/tertutup, tidak ada scroll yang tidak diinginkan, jarak aman, keyboard virtual.
3. Aksesibilitas: fokus keyboard, aria-label, kontras teks, tombol dapat dioperasikan tanpa mouse, reduced motion.
4. Performa: jumlah partikel, tidak ada memory leak (timer/raf/listener), lazy load.
5. Audio: sfx + musik per section konsisten, tidak menumpuk saat berpindah cepat.
6. Konsistensi gaya teks dan visual dengan section lama.
Keluaran: hanya file yang diperbaiki (kode lengkap) + daftar temuan singkat.
Saran: jika terlalu panjang, bagi menjadi 5A (Wishing + form), 5B (Secret Ending + HomeWarp), 5C (Gallery + audio + navigasi).

=====================================================================
FASE 6: Backend (Netlify Functions + Supabase)
=====================================================================
Hubungkan ke backend nyata. Stack: Netlify Functions (ESM/Node 18+) + Supabase (Postgres). Ganti isi src/services/wishes.js tanpa mengubah kontrak fungsi yang dipakai UI.
Saya mengeksekusi semuanya MANUAL. Sajikan sebagai langkah bernomor yang bisa saya ikuti: (a) SQL untuk ditempel di Supabase SQL Editor, (b) file function lengkap beserta path-nya, (c) isi netlify.toml, (d) env var yang diisi lewat Netlify dashboard (Site settings > Environment variables), (e) perintah terminal yang saya jalankan (npm i, netlify dev), beserta hasil yang seharusnya muncul agar saya tahu berhasil atau gagal. Jika ada error, saya akan menempelkan pesan error-nya ke chat ini.
Berikan:
1. SQL Supabase lengkap: tabel wishes (id uuid, display_name, is_anonymous, category, message, rating smallint 1 sampai 5, is_private bool, status enum pending/approved/rejected default 'pending', created_at). Constraint panjang pesan dan rating. RLS aktif: anon TIDAK bisa insert/select langsung; akses hanya via service key dari function. Index untuk sort/filter.
2. Netlify Function submit-wish: validasi ketat server-side (panjang, rating, kategori whitelist, trim, buang kontrol karakter), tolak jika honeypot terisi, rate limit sederhana (mis. per IP-hash, tanpa menyimpan IP mentah), filter kata kasar dasar, simpan status 'pending' (atau 'approved' jika memilih auto-publish; jelaskan opsi dan default ke pending). Pesan private tersimpan tapi tidak pernah dikembalikan ke gallery.
3. Netlify Function get-wishes: hanya status approved dan bukan private, mendukung sort, filter kategori, cursor pagination, agregat (rata-rata dan jumlah), header cache singkat.
4. Environment variable yang dibutuhkan (SUPABASE_URL, SUPABASE_SERVICE_KEY, dll.), netlify.toml (functions dir, redirect /api/*), cara test lokal dengan netlify dev.
5. Cara moderasi: langkah approve/reject lewat dashboard Supabase (Table Editor) dan query SQL siap pakai.
6. Penanganan error di UI (jaringan gagal, rate limit, validasi) dengan pesan ramah; fallback saat backend mati agar website tidak rusak.
7. Opsi lanjutan (jelaskan singkat, jangan implementasi kecuali diminta): Cloudflare Turnstile, notifikasi email saat ada wish baru.
Keamanan: service key tidak boleh ada di bundle front-end; jangan simpan IP/email; teks selalu dirender sebagai teks.
Keluaran: SQL, file function, netlify.toml, wishes.js, dan langkah deploy berurutan (singkat).
